## 一、planner.py（新版）

### ❌ 1. 关键词词典 value 错位一行

```python
"绿色方块": "blue_block",      # 绿色 → 蓝
"蓝色方块": "yellow_block",    # 蓝 → 黄，而 yellow_block 已被你删掉
```

`VALID_OBJS` 你改对了，但词典没跟着改。实测：

```
红色方块 -> red_block      ✅
绿色方块 -> blue_block     ❌ 去抓蓝的
蓝色方块 -> yellow_block   ❌ 物体不存在
```

改成：

```python
OBJ_KEYWORDS = {
    "红色方块": "red_block",   "红色": "red_block",
    "绿色方块": "green_block", "绿色": "green_block",
    "蓝色方块": "blue_block",  "蓝色": "blue_block",
}
```

### ❌ 2. LLM prompt 还是旧的 `yellow_block`

会绕成一圈：

> 模型照 prompt 输出 `yellow_block` → `_validate_schema` 判非法 → 降级关键词
> → 关键词照样吐 `yellow_block`（**离线路径不做校验**）→ `valid=True`，目标不存在

prompt 那行同步改成 `red_block / green_block / blue_block / null`。

### ❌ 3. 区域命名对不上

你用 `zoneA / zoneB`，真实场景是 `黄色区域 / 紫色区域`。
用户说「放到**紫色区域**」，中文里没有 A/B → **区域解析必失败**。
（我实测过，4 条真实指令全部 `valid=False`。）

### ❌ 4. Qwen 接口是旧版 + 模型已下线

```
旧：dashscope.aliyuncs.com/api/v1/services/aigc/text-generation/generation  model=qwen-turbo
新：dashscope.aliyuncs.com/compatible-mode/v1/chat/completions             model=qwen-plus
```

新版请求体是 `{"messages": [...]}`，返回取 `data["choices"][0]["message"]["content"]`。

### ❌ 5. `requests` 我们环境里没装

主线用标准库 `urllib`，就是为了不引依赖。要么换 urllib，要么在 `requirements.txt` 加上。

### ⚠️ 6. 关键词循环缺 `break`

现在是"后匹配的覆盖先匹配的"，结果由字典顺序决定。加一个 `break` 就稳了。

### ⚠️ 7. 正则 `\bA\b` 在中文里不生效

```
放到A区   -> 匹配不到   ← 中文是"词字符"，A 两边形不成单词边界
放到 A 区 -> 能匹配     ← 只有加空格才行
```

### ⚠️ 8. 离线路径不校验合法性

`parse_by_keyword` 返回的 `target_obj` 没跟 `VALID_OBJS` 比对，
所以能返回 `valid=True` + 一个不存在的物体，**比直接报错更难查**。

### 💡 9. 末尾测试用例还是旧的

还在测「拿黄色方块放到A区」，建议删掉或改成绿色，免得下次看误导自己。

## 二、vision.py

### ❌ 1. HSV 阈值脱离 `config.py` 另起一套

你在 vision.py 顶部重新定义了 `HSV_RANGES`，而项目里 `config.py` 已经有一份
（而且是实测标定过的，5/5 全中、误差 2~5 mm）。

两处并存的结果一定是**不同步**——改了这边忘那边。
阈值必须只在 `config.py` 里定义一份。

### ❌ 2. 命名跟项目对不上

你是 `red_block / green-block / blue_block / zoneA / zoneB`，
项目里是 `红色方块 / 绿色方块 / 蓝色方块 / 黄色区域 / 紫色区域`。

另外 **`green-block` 用了短横线**，其它 key 都是下划线，不一致。

### ❌ 3. 接口签名跟主线不一致

主线冻结的是：

```python
detect(cam, rgb, depth, name, is_block, top_layer=0.012) -> (世界坐标, 调试信息)
```

你的是 `detect_objects(img_rgb, depth_img, view_matrix, proj_matrix, ...)`。
`robot_sim.py` 调的是前者，直接替换会崩。

### ⚠️ 4. 只取外接矩形中心**单个像素**的深度

```python
ix, iy = int(cx), int(cy)
d = float(depth_img[iy, ix])
```

中心像素刚好落在噪点或边缘就会漂。主线是**取整个色块的点云再求质心**，
方块还额外取最高一层（顶面），压掉侧面带来的偏移——这也是能做到 2~5 mm 的原因。

### ⚠️ 5. 没有形态学去噪

主线有 `morphologyEx` 的 OPEN + CLOSE，滤掉小噪点和空洞。你这边直接 `inRange` 就找轮廓。

### ⚠️ 6. 同一颜色会返回**多个目标**

```python
for cnt in contours:
    if area < min_area: continue
    detect_result.append(item)     # 每个合格轮廓都加入
```

场景里若有反光或碎光斑，会返回两个 `red_block`，主控不知道该抓哪个。
主线是**只取最大的那个轮廓**。

### 💡 7. `min_area` 按分辨率自适应

`max(80, W*H/3000)` 这个思路比我固定的 40 好，可以保留。

### 💡 8. `confidence` 字段和防御性检查

置信度、RGB 维度校验、深度图尺寸校验、边界检查——这几条**你写得比我细**，我会吸收进主线。
`draw_overlay` 被注释掉了，如果不用可以删。

## 三、tune_hsv.py

### ❌ 1. 场景里什么都没有

```python
p.loadURDF("plane.urdf")     # 只有地面
```

没有桌子、没有方块、没有机械臂。**这个工具调不出方块的颜色**，
你看到的只有一片灰色地面。

### ❌ 2. 相机参数跟项目完全不同

| | 你的 | 项目（config.py） |
| --- | --- | --- |
| 位置 | `[1.2, 0, 0.8]` | `(0.50, -0.45, 1.25)` |
| 看向 | `[0, 0, 0.3]` | `(0.50, 0.0, 0.45)` |
| FOV | 60 | 55 |
| near/far | 0.1 / 5.0 | 0.05 / 3.0 |

**视角和光照都不一样，调出来的 HSV 套不到项目上。**

### ⚠️ 3. 调完要人工抄进 config.py

手动抄容易错。直接用 `python tools/sample_colors.py`——
它从**项目真实相机视角**采样每个目标的实际 RGB/HSV，打印出来照着填就行。

### 💡 4. 顺带说一句

现在的 HSV 阈值是实测标定过的、5 个目标全中，**没有理由换**，
除非你发现具体哪个识别不到。真要调，也请在真实场景里调。
